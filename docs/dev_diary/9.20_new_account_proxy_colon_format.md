# 9.20 — формат прокси при создании воркера: `host:port:user:pass`

## Что сделано

Модалка «Новый аккаунт» теперь принимает прокси в виде
`158.46.145.227:63795:user:pass` (как обычно отдают провайдеры),
а внутри конвертирует в `socks5://user:pass@host:port` перед
отправкой на бэк. Старая URL-форма также принимается (оставлена как
fallback на случай копипасты из других источников).

Бэкенд, БД, парсер `core/proxy.py`, ручки auth / proxy-check —
**не тронуты**. Существующие аккаунты в `accounts.proxy_primary/fallback`
продолжают работать as is.

## Файлы

- `modules/ui_web/src/components/dialogs/NewAccountDialog.tsx`:
  - добавлен helper `proxyToUrl(input)` с регуляркой
    `^([^:\s]+):(\d+):([^:\s]+):(.+)$`;
  - `submitForm` парсит оба поля, при невалидном формате — красный
    тост, запрос на `/auth/start` не уходит;
  - placeholder'ы и подпись под полями обновлены под новый формат.

## Почему так, а не иначе

- **Конвертация в UI, а не на бэке.** БД и парсер уже умеют URL-форму
  идеально, валидаций SOCKS5 много где разбросано — менять там
  парсер означает риск задеть auth-flow для уже работающих воркеров.
  В UI меняем только то, что показываем оператору.
- **Pass-through для URL-формы.** Если оператор скопирует старую
  строку (например, из заметок), форма её примет без претензий —
  одна и та же модалка работает в обе стороны без переключателей.
- **Регулярка терпит `:` в пароле.** Последняя группа `(.+)` —
  greedy. Это нужно, потому что некоторые провайдеры выдают пароли
  типа `pX:Y` — split с лимитом такие не вытащил бы.
- **Валидация — только на submit, не на каждый keystroke.** Поле
  длинное, ввод посимвольный, краснить его на лету было бы шумно.
  Оператор увидит ошибку только когда нажмёт «Отправить код».

## Что НЕ меняли

- `core/proxy.py` — продолжает разбирать `socks5://...` URL.
- `accounts.proxy_primary` / `accounts.proxy_fallback` — формат
  данных в БД тот же.
- `/system/proxy-check`, `modules/auth/...`, `modules/worker/wrapper.py` —
  ноль правок, всё работает как раньше.

## Проверка вручную

После рестарта UI (или сразу в dev — vite HMR подхватит):
1. «Новый аккаунт» → ввести `1.2.3.4:1080:user:pass` → отправить.
2. В `accounts.proxy_primary` должно лечь `socks5://user:pass@1.2.3.4:1080`.
3. Ввод любого мусора → красный тост «Прокси: неверный формат».
