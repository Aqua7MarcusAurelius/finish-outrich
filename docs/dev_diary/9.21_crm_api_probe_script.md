# 9.21 — песочница-разведчик CRM API (`scripts/crm_probe.py`)

## Что это

Перед тем как проектировать интеграцию с CRM коллеги
(см. `docs/INT_CRM_API_TOKEN_GUIDE.md`), нужно понять как **в реальности**
выглядят ответы их API: какие поля у лида, что приходит в
`request-new`, что есть в `preferences`. Гайд показывает только
обрывки.

Скрипт — одноразовый разведчик. Не часть основного приложения, не
запускается автоматически, не лезет в БД, не дёргает шину. Тупо
ходит в их API с нашим bearer-токеном и pretty-print'ит ответ.
Все запросы и ответы дублируются в `scripts/crm_probe.log`
(JSON Lines, без токенов).

## Файлы

- `scripts/crm_probe.py` — сам скрипт. CLI на argparse,
  HTTP-клиент `httpx` (уже есть в requirements). Команды:
  - `preferences` — текущие настройки L1 (gender_filter, max_concurrent_leads);
  - `chats` — что у нас уже за чаты;
  - `leads [--status X] [--search Y]` — что за лиды на нас привязаны;
  - `messages <username>` — переписка с конкретным лидом;
  - `request-new [--count N]` — ⚠ **реально забирает** лидов из пула.
    Перед вызовом — обязательный ввод `yes`, чтобы случайно не съесть.
- `.env.example` — две новые переменные `CRM_BASE_URL` и `CRM_API_TOKEN`
  (документация). Реальные значения — в `.env`, которая в `.gitignore`.

## Как запускать

```
docker compose exec app python scripts/crm_probe.py <command>
```

Запускаем внутри `app`-контейнера, потому что там уже стоит `httpx`
из `requirements.txt`. На хосте отдельный venv поднимать не надо.

## Почему так, а не иначе

- **Скрипт, а не endpoint в нашем FastAPI.** Это разведка, а не часть
  системы. Endpoint оставил бы за собой код, который потом надо
  удалять. Скрипт — просто файл, можно удалить, переписать, забыть.
- **`scripts/` папка**, не корень. Раньше у нас в корне валялись
  `recover_prompts.py`, `recovered.txt` и т.п. — мы их сами вычищали
  в 9.8. Стало понятно: одноразовые инструменты пора складывать
  в субдиректорию.
- **`.env` для токена.** Любой другой способ (CLI-arg, ENV-vars
  руками) либо засветит токен в shell history, либо потребует
  каждый раз вводить.
- **`yes`-конфёрм на `request-new`.** Эта команда **необратимо**
  вытаскивает лида из общего пула. Случайно нажать в shell — реальный
  риск. Простой текстовый конфёрм пресекает 99% таких случайностей.
- **Логирование в JSONL.** В стрессе разведки оператор быстро
  забывает «а что я делал три минуты назад». Лог — страховка.

## Что НЕ делал (намеренно)

- Не интегрировал в основное приложение.
- Не реализовал отправку сообщений / смену статусов лидов — это уже
  «работа», а не «разведка». Сначала надо понять, что вообще приходит.
- Не подключил WebSocket — для разведки HTTP достаточно.

## Дальше

Когда у тебя появится токен от коллеги:
1. Прописать `CRM_BASE_URL` и `CRM_API_TOKEN` в `.env`.
2. `docker compose exec app python scripts/crm_probe.py preferences` —
   убедиться что токен валиден.
3. `docker compose exec app python scripts/crm_probe.py leads` —
   посмотреть на текущее состояние без расходования лидов.
4. Перед `request-new` — убедиться что окей терять одного лида в
   процессе исследования.

Результаты разведки → решения по архитектуре полноценной интеграции
(модуль `modules/crm_leads/` или похожий — будем думать после).
