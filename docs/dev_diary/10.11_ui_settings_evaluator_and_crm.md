# 10.11 — UI: страница настроек с оценщиком и партнёрским CRM

**Дата:** 2026-05-17
**Этап:** 10.11

## Что сделано

В `/settings` добавили два новых раздела к существующему "Статусы диалогов":

1. **Оценщик лидов** — редактор `prompts/lead_evaluator_system.md` +
   четыре числовых параметра (таймеры тишины, ретраи парсинга).
2. **Партнёрский CRM** — статус подключения, размер пула, CRM
   preferences (read-only) + три параметра автозабора пула.

Это закрывает 10-ю главу проекта.

## LeadEvaluatorPanel

Две секции в одной странице:

**Промт-файл** — большой Textarea с содержимым `lead_evaluator_system.md`.
Сверху — путь до файла, снизу — список плейсхолдеров + кнопка "Сохранить промт".
Сохранение идёт через `PUT /lead-evaluator/prompt`.

**Таймеры и поведение** — четыре поля:
- `silence_to_obryv_hours` (4)
- `silence_to_close_hours` (48)
- `silence_check_interval_sec` (300)
- `parse_retries` (1)

Числовые input'ы, batch-PATCH через `/system/settings`. Каждое поле
показывает свой key (мелким моноширинным под лейблом) — оператор
видит точное имя для SQL-запросов / поиска по коду.

## PartnerCrmPanel

Три секции:

**Подключение** — live от `/partner-crm/health` (configured + pool_size).
Кнопка обновить.

**CRM preferences (read-only)** — прямой `fetch('/partner-crm/preferences')`,
показывает `ready_to_receive`, `max_concurrent_leads`, `gender_filter`,
`geo_filter` (это управляется на стороне партнёра, мы только смотрим).

**Параметры автозабора** — три поля:
- `partner_crm.poll_interval_sec` (60)
- `partner_crm.pool_low_threshold` (10)
- `partner_crm.refill_batch_size` (50)

Тот же UPDATE-only паттерн через `/system/settings`.

## Почему так, а не иначе

**Endpoints `/system/settings` — UPDATE-only.** Семантика "оператор
крутит существующие настройки, не создаёт новые". Все ключи приходят
из миграций. Если оператор передаст несуществующий key — игнорируется
(`UPDATE 0`), не падает с ошибкой. Защищаемся от опечаток без
дополнительного валидатора.

**batch PATCH одной транзакцией.** Если оператор крутит несколько
полей и одно из значений невалидное — все откатываются. На реальности
обычно либо всё сохраняется, либо ничего (он жмёт кнопку "Сохранить").

**`PartnerCrmPanel` дёргает `/partner-crm/preferences` напрямую fetch'ом**,
не через `api.*` обёртку. Один lone-вызов чтобы не плодить новый
метод. Если эндпоинт упадёт (CRM недоступна) — ловим в try/catch,
показываем ErrorBox.

**Раздел "Статусы диалогов" остался первым.** Это самый часто
используемый раздел, ничего не сломали.

**Сохраняется отдельной кнопкой каждая секция (промт vs таймеры).**
Не нагоняем мысль "сохранить всё" — оператор может крутить таймеры
не трогая промт. Дисабл-кнопки по `dirty` флагу.

## Проверка

```bash
curl http://localhost:8000/system/settings?prefix=lead_evaluator. | jq .items[].key
# "lead_evaluator.parse_retries"
# "lead_evaluator.silence_check_interval_sec"
# "lead_evaluator.silence_to_close_hours"
# "lead_evaluator.silence_to_obryv_hours"

curl -X PATCH http://localhost:8000/system/settings \
  -H "Content-Type: application/json" \
  -d '{"updates": {"lead_evaluator.parse_retries": "2"}}'
# {"updated": 1}
```

В UI — открыть `/settings`, выбрать "Оценщик лидов" / "Партнёрский CRM",
поправить значения, нажать сохранить. Бэйдж в LeadSettingsPanel
(на странице промта воркера) обновится при следующем рефреше.
