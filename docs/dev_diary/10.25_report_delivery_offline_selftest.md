# 10.25 — report_delivery: офлайн-самопроверка логики

**Дата:** 2026-06-09
**Этап:** 10.25

## Что сделано

Прогнали логику `ReportDeliveryService._handle` офлайн — без Telegram,
Docker и БД. Границы (шина, БД, MinIO, Redis, враппер) подменены фейками
через `sys.modules`; `core/events.py` берётся настоящий, так что сверяем
реальные имена событий. Результат: **20/20 проверок прошло** (exit 0).

## Файлы

- `scripts/report_delivery_selftest.py` — самодостаточный прогон,
  `python scripts/report_delivery_selftest.py`.

## Что покрыто

| Сценарий | Проверяем |
|---|---|
| A. не-success | `send_file` не зван, событий нет |
| B. success + группа | файл ушёл в верный `chat_id`; имя файла из ключа; `force_document`; подпись с воркером, `@партнёром`, полями оценщика; событие `report.delivered`; дедуп-флаг |
| C. повтор диалога | дедуп — второй раз не шлём |
| D. воркер без группы | `report.delivery_skipped`, дедуп не занят |
| E. ошибка отправки | `report.delivery_failed`, claim снят (повтор возможен) |
| F. протухшая сессия | `report.delivery_failed`, подключение сброшено, claim снят |

## Почему так, а не иначе

**Подмена через `sys.modules`, а не установка зависимостей.** Проект
Docker-овый (telethon/asyncpg/minio локально не стоят). Стаб границ
оставляет настоящим код под тестом и `core/events.py`, гоняется голым
`python` без сети и установок. `SessionExpired`/`ProxyUnavailable` берём из
фейкового `modules.worker.wrapper` — те же объекты, что ловит сервис.

**Логи сервиса заглушены (`logging.disable`).** Ветки E/F намеренно зовут
`log.exception` — это часть поведения; в выводе теста трейсбек был бы шумом.
