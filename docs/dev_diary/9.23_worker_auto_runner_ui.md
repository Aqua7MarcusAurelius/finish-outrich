# 9.23 — Worker Auto Runner: UI

## Что это

Поверх бэкенда из 9.22 — UI на странице «Диалоги». На карточке каждого
воркера появилось:
- Бейдж «авто» с пульсирующим зелёным кружком, когда автомат запущен.
- Пара кнопок **▶ Play / ⏸ Пауза** + **⚙** (настройки).
- Модалка настроек: очередь юзернеймов (textarea, по одному на строку),
  интервал в секундах, jitter, превью «следующая пауза будет в диапазоне
  X..Y минут», статус автомата сверху, кнопки Отмена/Сохранить.

## Файлы

Новые:
- `modules/ui_web/src/components/dialogs/AutoRunnerSettingsDialog.tsx` —
  модалка. Использует `useAutoRunner(accountId)` (react-query),
  локально хранит draft, на Save шлёт PATCH.

Поправлены:
- `modules/ui_web/src/types/api.ts` — типы `AutoRunnerState` и
  `AutoRunnerPatchBody`.
- `modules/ui_web/src/lib/api.ts` — четыре функции:
  `getAutoRunner / patchAutoRunner / startAutoRunner / stopAutoRunner`.
- `modules/ui_web/src/hooks/useAccounts.ts` — новый хук
  `useAutoRunner(accountId)` с `refetchInterval: 10_000`. Поллим,
  потому что бэк сам может выключить автомат (worker.stopped /
  worker.crashed), и UI должен это поймать без рефреша.
- `modules/ui_web/src/components/dialogs/AccountCard.tsx` —
  Play/Pause + Settings рядом с уже имеющимися Wipe/Промт/Start/Stop;
  тогл сам зовёт API через `api.startAutoRunner` / `stopAutoRunner`,
  parent передаёт только колбэк «открыть модалку».
- `modules/ui_web/src/pages/DialogsPage.tsx` — state
  `arSettingsAccount`, проброс `onAutoRunnerSettings`, рендер
  модалки.

## Почему так, а не иначе

- **`useAutoRunner` живёт ВНУТРИ каждого `AccountCard`.** Альтернатива
  «один глобальный батч-запрос на все воркеры» требует новой ручки
  на бэке. На 5-10 воркерах ~1 запрос/сек суммарно — терпимо. Если
  воркеров станет 50+, перейдём на батч.
- **Сам тогл (Play/Pause) обрабатывается внутри карточки**, parent
  получает только `onAutoRunnerSettings`. У тогла одна операция и
  она просто шлёт POST — не за что выносить её на уровень страницы.
- **Минимум `interval_sec = 60`** дублирован константой в фронте —
  чтобы number-input не давал ввести меньше. Бэк всё равно
  перепроверит (Pydantic `ge=60`), но UX лучше когда «не даёт
  ввести» вместо «принимает и валит ошибкой».
- **Превью «следующая пауза будет от X до Y»** — реальный диапазон
  для оператора, считается локально из текущих interval+jitter.
  Помогает не ошибиться (вписал 300+200 и видишь «5±3 мин»).
- **Бейдж «авто»** в шапке карточки — отдельная визуальная подсказка
  что автомат сейчас крутит этот воркер. Без него Play/Pause
  единственный сигнал, и его легко пропустить.

## Что НЕ сделано (намеренно)

- Лог автомата прямо в модалке. Сейчас вижу только `last_status` /
  `last_action_at` — это последняя строка. Подробные события —
  через страницу Event Log с фильтром `module=worker_auto_runner`.
  Дублировать UI не стал, пока никто не просил.
- Drag-n-drop для перестановки очереди. Textarea — самое простое:
  оператор сам управляет порядком в редакторе.
- Отдельный счётчик «осталось в очереди» — он виден через `parsedQueue.length`
  справа от label, этого достаточно.

## Проверка вручную

После рестарта `app` (бэк новый) и HMR в UI:
1. Карточка воркера показывает Wipe, Play/⚙, Промт, Start.
2. Воркер не running → Play disabled.
3. Запусти воркер → Play кликабельна.
4. Открой ⚙, вставь несколько юзернеймов, поставь `interval_sec=60`,
   `jitter_sec=15` → Сохрани.
5. Жми Play → бейдж «авто» загорается, в Event Log с фильтром
   `module=worker_auto_runner` — `auto_runner.started`.
6. Через минуту в Event Log должно появиться `auto_runner.lead_sent`
   (если юзернейм есть в TG) или `auto_runner.lead_skipped` (если не нашёл).
7. Останови воркер → автомат сам гаснет, бейдж пропадает в течение
   ~10 сек (поллинг useAutoRunner).
