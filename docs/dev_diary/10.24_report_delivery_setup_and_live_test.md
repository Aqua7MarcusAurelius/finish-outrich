## Разовая настройка (оператор)

1. **Авторизовать сервис-аккаунт.** Мастером «новый аккаунт» залогинить
   отдельный Telegram-аккаунт. Имя задать ровно `service` (или другое — но
   тогда то же значение прописать в `SERVICE_ACCOUNT_NAME`). После создания
   он автоматически скрыт из UI.
2. **Добавить его участником** в каждую группу выгрузки.
3. **Узнать `chat_id` групп.** Для приватных супергрупп id вида
   `-100…`. Способы: переслать сообщение из группы боту `@getidsbot` /
   `@username_to_id_bot`; либо посмотреть в логе нашего же приложения —
   при прогреве `get_dialogs` сервис-аккаунт уже видит группы.
4. **Заполнить карту** в `.env`:
   ```
   SERVICE_ACCOUNT_NAME=service
   REPORT_GROUP_MAP={"SAD_03_RU": -1001234567890, "JOKER_01_RU": -1009876543210}
   ```
   Ключ = имя воркера (`accounts.name`, как в префиксе имени файла отчёта).
5. **Перезапустить `app`** (карта читается из `.env` на старте).

## Живой прогон

1. `docker compose up -d app` (или рестарт). В логе ожидаем:
   ```
   report_delivery: сервис-аккаунт подключён
   ReportDelivery loop started: N групп в карте, сервис-аккаунт id=...
   ```
   Если карта пуста / аккаунт не найден — будет строка «доставка выключена»
   с причиной (это нормально, фича просто отключена).
2. Довести CRM-диалог замапленного воркера до `Завершен успешно`
   (оценщик/оператор ставит терминальный пузырь).
3. Проверить цепочку в ленте «События» (или `events_archive`):
   ```
   autochat | autochat.report_saved   | success | folder=success
   report_delivery | report.delivered  | success | dialog_id=… chat_id=…
   ```
4. Открыть группу выгрузки — там лежит HTML-файл
   `SAD_03_RU_@user_….html` с подписью (воркер, собеседник, поля
   оценщика, время).

## Диагностика

- `report.delivery_skipped reason=no_group_mapped` — воркер не в
  `REPORT_GROUP_MAP`. Добавить и перезапустить.
- `report.delivery_failed reason=session_expired` — сервис-аккаунт
  разлогинен, переавторизовать.
- `report.delivery_failed reason=<resolve/chat>` — сервис-аккаунт не в
  группе или неверный `chat_id`. Добавить участником / проверить id.
- Повторная отправка не происходит (дедуп `report_delivered:{dialog_id}`):
  чтобы переслать вручную — снять ключ в Redis или (план) дёрнуть
  будущий resend-эндпоинт.
