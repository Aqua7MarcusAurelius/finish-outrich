# 10.5 — Модуль lead_evaluator: LLM-судья закрытых диалогов

**Дата:** 2026-05-17
**Этап:** 10.5

## Что сделано

Создали модуль `modules/lead_evaluator/` — LLM-судью, который при
закрытии диалога анализирует переписку и выдаёт вердикт
(`success`/`archive`) + извлекает поля профиля лида (имя, возраст,
город, работа, интересы). Подключили consumer на шину
(`autochat.finished_by_llm`) и ручной API для оператора.

## Файлы

- `prompts/lead_evaluator_system.md` — дефолтный промт-файл
- `modules/lead_evaluator/__init__.py`
- `modules/lead_evaluator/errors.py` — `LeadEvaluatorError` → 4 наследника
- `modules/lead_evaluator/parser.py` — `parse_evaluator_response`, `EvaluationResult`
- `modules/lead_evaluator/prompts.py` — `build_evaluator_messages` (использует приватные хелперы `autochat.generation` для загрузки переписки + плейсхолдеров)
- `modules/lead_evaluator/service.py` — `LeadEvaluatorService` (consumer loop + evaluate)
- `modules/lead_evaluator/routes.py` — `/lead-evaluator/*` эндпоинты
- `api/main.py` — регистрация сервиса/таски/роутера

## Эндпоинты

| Метод | Путь | Что |
|---|---|---|
| POST | `/lead-evaluator/dialogs/{id}/evaluate` | Ручной запуск оценки (UI: "Завершить и оценить") |
| GET | `/lead-evaluator/dialogs/{id}/evaluation` | Сохранённая оценка для карточки диалога |
| GET | `/lead-evaluator/prompt` | Текст промта (для редактора) |
| PUT | `/lead-evaluator/prompt` | Сохранить новый промт |

## Поток одной оценки

```
[autochat.finished_by_llm] или [POST .../evaluate]
        │
        ▼ LeadEvaluatorService.evaluate(dialog_id)
1. SELECT dialog (account_id, gender, from_crm)
2. build_evaluator_messages — собрать [system, user] для chat_completion
   • рендерит prompts/lead_evaluator_system.md с подставленными значениями
   • переиспользует partner_profile + conversation history из autochat
3. publish lead_evaluator.started
4. openrouter.chat_completion(..., model=OPENROUTER_MODEL_EVALUATOR)
   • При непарсе verdict — 1 ретрай (parse_retries из settings)
5. UPSERT в lead_evaluations (UNIQUE(dialog_id))
6. UPDATE dialogs.partner_crm_terminal_reason
   • verdict=success  → 'ready_for_transfer'
   • verdict=archive  → 'no_response'
7. dialog_statuses.set_dialog_status — терминальный пузырь
   • success → "Завершен успешно"
   • archive → "Завершен провал"
8. publish lead_evaluator.completed  (либо .parse_failed если парсинг сломан)
```

`dialog.status_changed` уже публикуется внутри `dialog_statuses.set_dialog_status`
— это и есть сигнал для `partner_crm` (юнит 10.8) запушить финальный
статус в CRM.

## Парсер

Регулярки по 6 тегам: `<verdict>`, `<name>`, `<age>`, `<city>`,
`<workplace>`, `<interests>`. Всё остальное в ответе LLM (рассуждения,
комментарии) игнорируется.

- `<verdict>` обязателен. Без него `parse_succeeded=False`.
- `<age>` — берём первое число 10-120 из значения тега. "27 лет" → 27.
- Остальные строковые — `strip()` + обрезка до 500 символов.

## Ретрай и защитный дефолт

`lead_evaluator.parse_retries` (по умолчанию `1`) → до **двух** попыток
запроса в LLM. Если обе без `<verdict>` — фиксируем `parse_succeeded=False`,
запись делаем с `verdict='archive'` (защитно — лида не повышаем без
доказательств), публикуется `lead_evaluator.parse_failed`. В юните 10.7
эта запись приведёт к тому что HTML-отчёт попадёт в папку `archive/`
для ручного разбора.

## Защита от двойного запуска

`_running_dialog_ids` (set + lock) — если на один и тот же диалог
прилетают параллельно `autochat.finished_by_llm` И ручной API
запрос, второй вернёт `409 EVALUATION_ALREADY_RUNNING`. Это
предотвращает дубли LLM-вызовов и race на UPSERT.

## Почему так, а не иначе

**Импорт приватных хелперов `autochat.generation`.** Чтобы не
дублировать ~80 строк подзагрузки истории и подстановки плейсхолдеров,
импортируем `_load_partner_info_for_dialog`, `_load_turns`,
`_format_history_text`, `_load_message_stats`, `_load_worker_name`,
`PartnerInfo`. Это сознательная coupling — если autochat сильно
изменит сигнатуры, оценщик тоже поправим. Альтернативой было бы
вытащить эти хелперы в `core/conversation_render.py`, но это уже
рефактор autochat — за рамками этапа 10.

**Маппинг verdict→pubble через label лукап.** В service.py читаем
`dialog_statuses` по label `"Завершен успешно"` / `"Завершен провал"`,
чтобы получить `status_id`. Это работает потому что мы пересидили
каталог миграцией 0012 с известными лейблами. Если оператор
переименует пузырь — оценщик потеряет привязку и логнёт warning.
Защита — UI потом не даёт переименовывать терминальные пузыри
(или дать, но с предупреждением; вне scope этого юнита).

**`partner_crm_terminal_reason` пишет lead_evaluator, не partner_crm.**
Формально partner_crm владеет общением с CRM, но эта колонка —
"что мы хотим послать", не "что мы послали". Пишем её там, где
принимаем решение (оценщик), читает partner_crm в момент push'а.
Один писатель.

**Температура 0.4.** Между жёсткой 0 (выдавал бы однообразные шаблоны)
и 0.7 у autochat (нужен креатив в диалоге). Оценщик — задача
классификации, низкая температура достаточна.

## Проверка

`/lead-evaluator/prompt` отдаёт содержимое файла:
```bash
curl http://localhost:8000/lead-evaluator/prompt | jq -r '.path'
# /app/prompts/lead_evaluator_system.md
```

Парсер на тестовых строках:
```python
parse_evaluator_response('''
<verdict>success</verdict>
<name>Маша</name>
<age>27 лет</age>
<city>Новосибирск</city>
''')
# verdict='success' name='Маша' age=27 city='Новосибирск' parse_succeeded=True
```

End-to-end проверка с реальным LLM пойдёт когда первый CRM-лид
дойдёт до `<finishdialog/>`. До того можно вручную дёрнуть
`POST /lead-evaluator/dialogs/{id}/evaluate` на закрытом диалоге.

## Открытые вопросы

- Сейчас `set_dialog_status` зовётся только если нашли пузырь по
  лейблу. Если оператор переименовал — оценщик пишет warning и
  завершается без терминала. Стоит в UI заблокировать переименование
  терминальных или дать им стабильный slug — задел на 10.10.
- Если у диалога ещё нет ни одного сообщения (race с timer'ом) —
  оценщик отработает на пустой переписке. LLM скорее всего вернёт
  `archive`, что нормально. Логику "минимум N сообщений" не делаем —
  пусть LLM сама решит.
