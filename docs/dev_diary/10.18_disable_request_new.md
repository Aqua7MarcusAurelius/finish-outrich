# 10.18 — Отключаем `request-new` (берём только назначенных)

**Дата:** 2026-05-22
**Этап:** 10.18

## Что сделано

Полностью отключили в `refill_pool` фазу 2 — `POST /api/l1/leads/request-new`,
которая «таскала» лидов из общего пула партнёра. Теперь забираем только
тех, кого партнёр **сам назначил** на наш профиль (`?status=new`).

## Зачем

`request-new` берёт лидов из общего пула партнёрской CRM —
тех самых, за которыми охотятся другие L1-операторы у партнёра. По
сути мы «воровали» большой кусок их потока. Партнёр предпочитает
сам распределять: что-то назначает нам через свои правила, а мы
просто работаем с тем что нам прислали.

## Файлы

- `modules/partner_crm/service.py:refill_pool` — убрал phase 2 целиком.
  Возвращаемое значение `phase ∈ {"assigned", "empty"}`.
- `modules/ui_web/src/lib/api.ts` — обновил TS-тип ответа `partnerCrmRefill`
  под новый формат (`phase` + `from_request_new=0` всегда).
- `modules/ui_web/src/components/settings/LeadSettingsPanel.tsx`:
  - кнопка теперь «Подтянуть назначенных» (была «Забрать N лидов сейчас»).
  - тост-сообщение разнесено на два случая: `empty` («нет назначенных»)
    и `assigned` («подтянуто из N назначенных»).

## Что НЕ трогал

- `client.request_new_leads(count)` остался в `client.py`. Его никто не
  зовёт, но не удаляю — мало ли понадобится «спасательная кнопка» в
  будущем.
- Параметр `count` в `/pool/refill` остался для API-совместимости. Сейчас
  возвращается в ответе как `requested` для информативности, на логику
  не влияет.
- Сторож пула (`poller.py`) зовёт `refill_pool(refill_batch_size)`
  как и раньше. Просто теперь это работает в режиме «забрать всех
  назначенных».

## Поведение после фикса

| Сценарий | До (10.13) | После (10.18) |
|---|---|---|
| На профиле есть `lead_status=new` | Забираем всех | Забираем всех |
| На профиле пусто | request-new(count) на общий пул | **Ничего не делаем**, log + событие |
| Сторож тикает каждые 60с при пустом профиле | Каждый тик качает 50 лидов из общего пула | Нул-операция, ждём пока партнёр назначит |

После того как docker встанет, прогнать:

```bash
curl -X POST http://localhost:8000/partner-crm/pool/refill \
  -H "Content-Type: application/json" -d '{"count":5}' | jq

# Если есть назначенные: phase=assigned, inserted=N
# Если пусто:           phase=empty, inserted=0
```

И посмотреть в events:

```sql
SELECT type, data->>'phase' AS phase, data
FROM events_archive
WHERE module='partner_crm' AND type='partner_crm.pool_refilled'
ORDER BY time DESC LIMIT 5;
```

Не должно быть событий с `from_request_new > 0`.
