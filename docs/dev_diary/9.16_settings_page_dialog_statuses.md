# 9.16 — страница `/settings` и редактор статусов

## Что сделано

Появилась вкладка «Настройки» в верхней навигации с собственной
страницей `/settings`. Левый саб-нав, пока один пункт — «Статусы
диалогов». Внутри inline-редактор каталога: создать, переименовать,
перекрасить, поменять порядок (↑/↓), удалить.

## Файлы

- `modules/ui_web/src/pages/SettingsPage.tsx` — контейнер страницы:
  левая колонка с саб-навом (один пункт), правая — текущая панель.
- `modules/ui_web/src/components/settings/DialogStatusesPanel.tsx` —
  список редактируемых строк (swatch + нативный color picker + поле
  hex + поле лейбла + ↑/↓ + удалить) + кнопка «Добавить статус».
- `modules/ui_web/src/lib/api.ts` — функции каталога:
  `listDialogStatuses / createDialogStatus / updateDialogStatus /
  deleteDialogStatus`.
- `modules/ui_web/src/hooks/useAccounts.ts` — новый хук
  `useDialogStatuses()` поверх react-query с `staleTime: 60_000`
  (каталог меняется редко). Инвалидация — вручную после mutate.
- `modules/ui_web/src/App.tsx` — новый route `/settings`.
- `modules/ui_web/src/components/layout/AppShell.tsx` — таб «Настройки»
  с иконкой `Settings` от `lucide-react`.

## Почему так, а не иначе

- **Саб-нав слева на странице настроек**, а не серия отдельных
  роутов вроде `/settings/statuses`, `/settings/foo`. Сейчас один
  пункт, но позже там появятся «AutoChat», «Глобальные параметры»
  и т.п. — добавить пункт = 1 строка в `SECTIONS[]`, без правки
  роутинга.
- **Inline-edit с autosave по blur/Enter**, без кнопки «Сохранить».
  Каталог мелкий, операции дешёвые, лишняя кнопка только тормозит
  оператора. На неуспех — toast + откат локального draft.
- **Нативный `<input type="color">` + текстовое поле hex.**
  Пикер — для тех, кто не помнит коды, текст — для копи-паста точного
  значения. Оба связаны через общий `color` state. Hex принимаем
  с # и без — нормализуем перед PATCH'ем.
- **Reorder через ↑/↓**, не через drag. Без зависимости от
  `@dnd-kit` (которого в проекте нет) и без HTML5 drag-quirk'ов.
  Реализация — просто swap `sort_order` у соседних строк через
  два параллельных PATCH'а. Если оператор начнёт массово
  перетряхивать порядок — заведём drag, пока не нужно.
- **`useDialogStatuses` с `staleTime: 60_000`.** Каталог меняется
  редко, поэтому 60 секунд кэша — компромисс между «не дёргаем
  сервер на каждое открытие страницы диалогов» и «изменения видны
  быстро». После mutate в самой панели инвалидируем явно — UI
  обновляется мгновенно.
- **`confirm()` на удаление**, не модалка как у Wipe-кнопки. Удаление
  пузыря почти не деструктивно (диалоги получают `status_id = NULL`,
  ничего не теряется), поэтому отдельная модалка с вводом строки
  была бы overkill.

## Что в следующем коммите

`DialogListItem` сейчас всё ещё захардкожен на 4 ключа через адаптер
из 9.15. Следующий коммит подменит его на динамический рендер из
`useDialogStatuses()` и снимет адаптер из `api.ts`.

## Открытые вопросы

- SSE-инвалидация `useDialogStatuses` по событию
  `dialog_statuses.catalog_changed` для случая «двое операторов
  одновременно редактируют каталог». Сейчас второй увидит изменения
  через 60 сек (`staleTime`) или после своего refetch. Если станет
  тесно — подключим к существующему SSE-потоку `/events/stream`.
