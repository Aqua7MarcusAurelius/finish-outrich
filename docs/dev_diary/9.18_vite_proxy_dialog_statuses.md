# 9.18 — vite proxy для `/dialog-statuses`

## Симптом

На `/settings` → «Статусы диалогов» — красный ErrorBox
«Не удалось загрузить статусы — `GET /dialog-statuses -> 404`».
Бэк-ручка отвечает корректно при прямом `curl localhost:8000/dialog-statuses`
(возвращает 4 сидированных пузыря).

## Что было не так

Vite-dev на `:3000` проксирует на FastAPI только перечисленные префиксы.
Если префикса нет — vite считает запрос SPA-маршрутом и отдаёт `index.html`
со статусом 404 (или 200 с HTML, что тоже ломает JSON-парсер). В
комментарии к `proxy` блоку в `vite.config.ts:26-28` это явно описано
как известный подводный камень.

В 9.15 я добавил роут `POST /dialog-statuses` на бэке, но проксирующий
префикс в vite.config.ts не прописал — поэтому фронт его в dev-режиме
не видел.

## Файлы

- `modules/ui_web/vite.config.ts` — добавлен префикс `/dialog-statuses`
  в список proxy. Колонки выровнены пробелами (мелкий косметический
  bonus — иначе разная длина ключей).

После правки нужен рестарт UI-контейнера (vite.config.ts по HMR не
перечитывается).

## Почему так, а не иначе

- **Не хочу делать общий `*` proxy на бэк.** Это спрятало бы такие
  ошибки и одновременно мешало бы SPA-маршрутизации (например, наш
  `/settings` — это путь фронта, не бэка).
- **Не объединял с другим коммитом.** Это конкретный фикс инфраструктуры,
  отдельная история в логе помогает быстрее находить «когда мы
  забывали добавлять префикс» — а это, видимо, будет повторяться при
  добавлении новых модулей.

## Что проверить вживую

После рестарта UI:
```
curl -o /dev/null -w "%{http_code}\n" http://localhost:3000/dialog-statuses   # 200
```
В браузере: `/settings` → «Статусы диалогов» загружают каталог, CRUD
работает.
