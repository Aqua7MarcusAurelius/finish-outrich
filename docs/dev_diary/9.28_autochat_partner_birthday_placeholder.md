# 9.28 — плейсхолдер `{partner_birthday}` в autochat

## Что это

Пятый и последний коммит фичи «дотягиваем профиль один раз и
используем в промптах». Учит autochat подставлять день рождения
собеседника в шаблон.

`{partner_bio}` начал работать ещё в 9.27 (после того как peer_profile
дотянул и записал в `dialogs.bio`) — у него уже был и плейсхолдер
и SELECT. С днём рождения сложнее: его в БД хранят теперь три
поля (`birthday_day`, `birthday_month`, `birthday_year`), а в промпт
надо подставлять одной строкой.

## Файлы

- `modules/autochat/generation.py`:
  - Топ-докстринг (раздел «Поддерживаемые плейсхолдеры») — добавлена
    запись про `{partner_birthday}` с указанием формата.
  - Новая функция-хелпер `_format_birthday(day, month, year) -> str`:
    - `""` если день или месяц отсутствуют (тогда плейсхолдер исчезнет
      из промпта чисто, без артефактов);
    - `"DD.MM"` если года нет;
    - `"DD.MM.YYYY"` если год есть.
    `zfill` через `:02d` / `:04d` — единый вид независимо от
    однозначных чисел.
  - `PartnerInfo`:
    - Поле `birthday: str = ""` (отформатированная строка, не три
      инта — потребители не должны заново форматировать).
    - `from_dialog_row` — берёт три новых поля из row и форматирует.
    - `from_resolved_profile` — оставлен пустым с комментарием
      «здесь birthday не приходит, см. peer_profile»; resolve_username
      не делает GetFullUserRequest.
  - `_build_placeholders` — `"partner_birthday": partner.birthday`.
  - `_load_partner_info_for_dialog` — SELECT расширен на три новых
    колонки.

## Соответствие принципам

- **Незнакомый ключ остаётся литералом** (`_render` — без изменений):
  если оператор написал `{partner_birthday}` до этой фичи — он бы
  увидел литерал в превью и понял, что плейсхолдера нет. Теперь
  он его получает.
- **Не плодим конструкции.** `_format_birthday` — пять строк, рядом
  с `_strip_comments`. Не отдельный модуль, не утилитный пакет.
- **`PartnerInfo` остался frozen-dataclass.** Новое поле — дефолт
  пустая строка, обратная совместимость с конструкцией `PartnerInfo()`
  без аргументов (используется в превью fallback'е).

## Проверка end-to-end после миграции

Что должно произойти, если оператор:
1. Накатит миграцию `0011`.
2. Запустит app.
3. Воркер получит первое сообщение от @newuser, у которого в TG
   указан bio «менеджер, г.Москва» и день рождения 14 мая 1990.

Ожидаемый поток событий в Event Log (фильтр по dialog_id):
```
worker:  message.received
history: message.saved
history: dialog.created           ← новый
peer_profile: dialog.profile.fetched   ← новый
history: (тихо UPDATE dialogs)
```

В `dialogs` для этой строки появятся `bio='менеджер, г.Москва'`,
`birthday_day=14`, `birthday_month=5`, `birthday_year=1990`.

В следующий раз, когда AutoChat будет генерить ответ — `{partner_bio}`
подставит bio, `{partner_birthday}` → `"14.05.1990"`.

Если год не указан → `"14.05"`. Если день рождения вообще не задан →
плейсхолдер просто исчезает (пустая строка), промпт остаётся чистым.

## Что НЕ сделано

- UI карточки диалога: не показывает `bio` и `birthday_*` явно —
  по-прежнему рендерится только в плейсхолдере промпта. Если
  оператору понадобится видеть в боковой панели — добавим отдельным
  юнитом (поля в API уже отдаются с 9.25).
- Ручная кнопка «дотянуть профиль повторно» — пока не нужна;
  COALESCE в `_on_dialog_profile_fetched` всё равно не перетёр бы
  существующие значения, а первая дотяжка идёт автоматически.
