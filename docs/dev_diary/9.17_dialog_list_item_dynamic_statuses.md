# 9.17 — DialogListItem рендерит pill из динамического каталога

## Что сделано

`DialogListItem` больше не знает про 4 захардкоженных статуса.
Pill (точка в правом верхнем углу строки) рисуется по цвету из
`dialog.status.color`, dropdown в строке собирается из живого
каталога `useDialogStatuses()`. Удалили временный адаптер из
`api.ts`, который мостил старый enum-API на новый бэкенд.

## Файлы

- `modules/ui_web/src/types/api.ts` — убрали `DialogUserStatus` enum,
  ввели `DialogStatusRef = { id, label, color }`. У `DialogSummary`
  поле `user_status` → `status: DialogStatusRef | null`.
- `modules/ui_web/src/lib/api.ts`:
  - убрали `_LEGACY_STATUS_BY_ID` / `_LEGACY_STATUS_ID_BY_KEY`;
  - `adaptDialog` теперь просто пробрасывает `d.status` без
    маппинга на старые ключи;
  - `setDialogStatus(dialogId, statusId: number | null)` —
    подпись поменялась с enum на id, тело PATCH тоже.
- `modules/ui_web/src/components/dialogs/DialogListItem.tsx`:
  - убрали `STATUS_OPTIONS` / `NO_STATUS` / `statusOption()`;
  - используем `useDialogStatuses()` (react-query);
  - state хранит `pendingId: number | null | undefined`
    (undefined = нет пендинга, null = «снять статус», id = выбран
    конкретный пузырь);
  - точка в pill рисуется через `style={{ backgroundColor }}`
    с цветом из эффективного статуса;
  - dropdown собирается из каталога (`sortedCatalog`), пункт «Без
    статуса» добавлен отдельно ниже разделителя, есть состояние
    «каталог пуст — заведи в Настройки».

## Почему так, а не иначе

- **`pendingId` хранит число, полную карточку ищем в каталоге.**
  Альтернатива — хранить весь `DialogStatusRef` в pending — была
  бы дублированием информации (карточка живёт в каталоге, мы и так
  его сюда тащим). Один источник истины проще.
- **Inline-style для цвета**, а не tailwind-классы. У оператора hex
  свободный, статически класс не сгенерируешь. `style` —
  единственный способ; даёт гарантированный выбранный оператором
  тон вне зависимости от theme tokens.
- **Adapter снят целиком, не оставлен «на всякий случай».** Адаптер
  был переходным мостиком (9.15 → 9.17). Жить с ним дальше = ловить
  баги когда оператор переименует id=1 и UI продолжит звать его
  «Общаемся». Лучше резко и наглядно — `DialogSummary.status` теперь
  честно отражает каталог.
- **Состояние «каталог пуст».** Технически возможно после массового
  удаления всех пузырей в Настройках. Dropdown в этом случае
  показывает приглашающее сообщение, а не белый пустой блок.

## Что осталось разрешённым на будущее

- Реактивная инвалидация каталога по SSE-событию
  `dialog_statuses.catalog_changed`. Сейчас `staleTime: 60_000` —
  норма для одного оператора, тесно станет только если двое будут
  одновременно редактировать каталог и менять статусы диалогов.
- Программное проставление статуса. Бэкенд готов: достаточно где-то
  в listener'е событий шины импортировать
  `modules.dialog_statuses.service.set_dialog_status` и звать с
  `source="event:<type>"`. Сам listener — отдельная задача.
