# 10.14 — Fix: автозапуск оценщика после `<finishdialog/>`

**Дата:** 2026-05-19
**Этап:** 10.14 (баг-фикс с прод-тестирования)

## Что было сломано

Bug-report: `docs/fix/lead_evaluator_auto_trigger_broken.md`.

Кратко: publisher `autochat.session._publish_finished_by_llm` клал в
payload только `{session_id}`. Consumer `lead_evaluator.service._on_finished_by_llm`
ждал `data.dialog_id` и при его отсутствии **молча возвращался**. Из-за
рассинхрона контракта весь авто-flow (оценщик → пузырь → отчёт → push в
CRM) не запускался после `<finishdialog/>`. Ручной тычок «Оценить»
работал, потому что там dialog_id передавался явно.

## Что сделал

Применил **оба** варианта из bug-report'а:

### 1. Publisher — кладёт `dialog_id` в payload

[`modules/autochat/session.py:786-806`](../../modules/autochat/session.py#L786-L806)

```python
data: dict[str, Any] = {"session_id": self.id}
if self.dialog_id is not None:
    data["dialog_id"] = self.dialog_id
```

`self.dialog_id` известен сессии — `INSERT autochat_sessions` идёт в
`create_session` уже с заполненным dialog_id (history создаёт диалог
через publish message.received в той же транзакции).

### 2. Consumer — defensive-резолв через `session_id`

[`modules/lead_evaluator/service.py:_on_finished_by_llm`](../../modules/lead_evaluator/service.py)

Если `data.dialog_id is None` — резолвим через `autochat_sessions` по
`session_id`. Это даёт обратную совместимость со старыми событиями в
стриме и страховку от будущих рассинхронов.

### 3. Silent drop → log.warning

Вместо молчаливого `return` теперь:

```python
log.warning(
    "lead_evaluator: autochat.finished_by_llm без dialog_id "
    "(session_id=%s) — пропускаем",
    session_id,
)
```

Будущие рассинхроны контрактов будут видны в логах.

## Проверка

Эмитировал событие со «старым контрактом» (только `session_id=48` от
существующей сессии с `dialog_id=617`):

```python
await bus.publish(
    module=Module.AUTOCHAT,
    type=EventType.AUTOCHAT_FINISHED_BY_LLM,
    data={"session_id": 48},   # БЕЗ dialog_id
)
```

Результат в `events_archive` через 3 секунды:

```
lead_evaluator.started   in_progress  source=autochat.finished_by_llm  dialog_id=617
lead_evaluator.completed success      source=autochat.finished_by_llm  dialog_id=617
```

Defensive-резолв сработал — `dialog_id` подтянулся из `autochat_sessions`.

## Что **не** делал из bug-report'а (отложено)

1. **Жёсткий path в миграции 0012 для `dialog_statuses`** — оператор накастомил
   2 пузыря, миграция не пересеяла, `lead_evaluator` ругался warn'ом «системного
   пузыря нет». Оператор перевыставил вручную. Это правильное поведение
   миграции (не сносить чужие данные), но недостающие системные lейблы
   стоит добавить миграционно поверх кастомных. Сейчас этого делать не буду —
   нужен отдельный диалог о маппинге `id`'ов кастомных пузырей.

2. **silence_watcher как подписчик `autochat.finished_by_llm`** — это был
   workaround на случай если оценщик не успевает. С фиксом не нужен.

3. **Стартап-чек на наличие 6 канонических пузырей** — полезно но
   опционально. Запишу в отдельный TODO.
