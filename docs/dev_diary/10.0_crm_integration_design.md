# 10.0 — Интеграция с партнёрской CRM: дизайн

**Дата:** 2026-05-17
**Этап:** 10 (новая глава — переход от ручной вбивки лидов к работе через CRM)
**Ветка:** `beta` (отрезана от `main@b13f3f1`)

## Контекст

До этого этапа поток лидов был полностью ручной: оператор вбивал `@username`
в `worker_auto_runner`, диалоги создавались автоматически при первом сообщении,
операторские статусы (`dialog_statuses`) ставились вручную.

Партнёрская CRM (см. `docs/INT_CRM_API_TOKEN_GUIDE.md`) даёт нам пул лидов
и принимает обратно один из четырёх статусов. Мы становимся для CRM L1-AI
оператором. Задача — заменить ручной поток конвейером "CRM → авторазговор →
оценщик → CRM" с минимальными правками текущей архитектуры.

## Принципы, которые зафиксировали в обсуждении

1. **CRM — внешний контур. Свои сущности не плодим.** Лид = диалог.
   Никакой таблицы `leads`. Связь с CRM держится колонкой на `dialogs`.
2. **С CRM общаемся ровно два раза за лида**: при взятии в работу (`/start`)
   и при финальном закрытии (`/status`). Между этими двумя касаниями партнёр
   ничего о статусе не слышит — наши пузыри живут локально.
3. **Любая межмодульная коммуникация — через шину.** `partner_crm` не дёргает
   `autochat` напрямую, оба слушают/публикуют события.
4. **Каждая таблица — собственность одного модуля.** Новые таблицы
   (`crm_lead_pool`, `lead_evaluations`) принадлежат своим модулям.
5. **Промты редактируются вживую** — файлы в `prompts/`, как у autochat.

## Новые модули

| Модуль | Зона ответственности |
|---|---|
| `partner_crm` | HTTP-клиент к партнёрской CRM (httpx), poller для пула, push статусов |
| `lead_evaluator` | LLM-оценка закрытого диалога, извлечение полей о лиде |

`autochat` дорабатывается, но остаётся в текущих границах. `worker_auto_runner`
получает альтернативный источник лидов (пул), сохраняя per-worker очередь для
ручного режима.

## Источник лидов — переключатель на воркере

```
accounts.lead_source enum('manual', 'partner_crm') DEFAULT 'manual'
```

- `manual` — воркер берёт `@username` из собственной `worker_auto_runners.queue`
  (текущее поведение, ничего не ломается).
- `partner_crm` — воркер на тике пикапит запись из общего пула `crm_lead_pool`
  с учётом своего фильтра по полу.

```
accounts.target_gender enum('any', 'female', 'male') DEFAULT 'any'
```

В UI у воркера в режиме `manual` селект `target_gender` скрыт/неактивен.
При `partner_crm` — активен.

## Пул лидов из CRM

Общий, не per-worker — чтобы офлайн-воркер не зависал на своей очереди.

```
crm_lead_pool
├── id PK
├── username   text UNIQUE
├── gender     text NULL              -- 'female' | 'male' | NULL
└── fetched_at timestamp
```

**Сторож пула** (фоновая задача в `partner_crm`) раз в `partner_crm.poll_interval_sec`
секунд:
1. SELECT COUNT(*) FROM crm_lead_pool.
2. Если < `partner_crm.pool_low_threshold` (дефолт 10) и есть хотя бы один
   аккаунт с `lead_source = 'partner_crm'` и активным воркером →
   `POST /api/l1/leads/request-new {count: partner_crm.refill_batch_size}`
   (дефолт 50).
3. Полученные лиды INSERT в `crm_lead_pool`.

**Забор воркером.** При тике воркера с `lead_source = partner_crm`:
```sql
SELECT * FROM crm_lead_pool
WHERE gender IS NULL
   OR $target_gender = 'any'
   OR gender = $target_gender
ORDER BY fetched_at
LIMIT 1
FOR UPDATE SKIP LOCKED;

DELETE FROM crm_lead_pool WHERE id = $1;
```
Усваивает username + gender, идёт в `autochat/start`.

## Колонки на `dialogs`

| Колонка | Тип | Смысл |
|---|---|---|
| `gender` | text NULL | пол лида ('female'/'male'/NULL — для ручных) |
| `from_crm` | bool DEFAULT FALSE | лид из партнёрского CRM (нужно ли пушить статус) |
| `partner_crm_terminal_reason` | text NULL | какой код пушим в CRM при финализации (`ready_for_transfer` / `invalid` / `no_response`) |

`dialogs.username` уже есть и совпадает с CRM-идентификатором — отдельная
колонка `partner_crm_id` не нужна.

## Локальные статусы — 6 пузырей

Расширяем `dialog_statuses` колонкой `partner_terminal_status text NULL`.
Если заполнена → пузырь терминальный → финализация лида.

Сидится при миграции:

| Пузырь | Цвет | partner_terminal_status | Тип |
|---|---|---|---|
| Невалид | red | `invalid` | терминальный (тех-фейл) |
| Первый контакт | gray | NULL | промежуточный |
| Общение | blue | NULL | промежуточный |
| Обрыв | amber | NULL | промежуточный (4ч тишины после ответа) |
| Завершен успешно | green | `ready_for_transfer` | терминальный |
| Завершен провал | red | `no_response` | терминальный (архив оценщика + 2 суток молчания) |

Существующие пузыри (Общаемся, Ждём ответ, Готово, Провал) при миграции:
если набор статусов в БД совпадает с дефолтным — заменяем на новый
набор. Если оператор уже модифицировал — оставляем и логируем
несоответствие на шину (не пытаемся угадать что слать в CRM).

## Цепочка статусов

```
[autochat /start]
   ├─ resolve/send упал                    → Невалид → CRM invalid
   └─ ОК                                    → Первый контакт
                                                │
                                                ├─ 2 сут молчания           → Завершен провал → CRM no_response
                                                │
                                                └─ лид ответил              → Общение
                                                                              │
                                                                              ├─ 4ч тишины              → Обрыв ⇄ Общение (вернулся)
                                                                              │                            │
                                                                              │                            └─ 2 сут от Обрыва        → Завершен провал → CRM no_response
                                                                              │
                                                                              └─ <finishdialog/> от LLM
                                                                                    │
                                                                                    ▼
                                                                          [lead_evaluator]
                                                                                    ├─ verdict=success     → Завершен успешно → CRM ready_for_transfer
                                                                                    ├─ verdict=archive     → Завершен провал → CRM no_response
                                                                                    └─ парсинг сломан + ретрай → Завершен провал → CRM no_response (отчёт в archive/)
```

Оператор в любой момент может выставить любой пузырь вручную — терминальные
триггерят push в CRM, промежуточные — нет.

## Оценщик — модуль `lead_evaluator`

**Промт-файл** `prompts/lead_evaluator_system.md` (как у autochat — редактируется
вживую, HTML-комментарии вырезаются). Поддерживаемые плейсхолдеры:

| Плейсхолдер | Что подставляется |
|---|---|
| `{current_time}` | UTC сейчас |
| `{conversation_history}` | вся переписка с ролями и датами |
| `{partner_username}` | @handle лида |
| `{partner_first_name}`, `{partner_last_name}` | из TG-профиля |
| `{partner_bio}` | bio из TG |
| `{partner_birthday}` | если знаем (день/месяц/год) |
| `{partner_gender}` | для CRM-лидов |

**Модель.** `OPENROUTER_MODEL_EVALUATOR` (дефолт `anthropic/claude-opus-4-7`).

**Триггеры:**
1. `autochat.finished_by_llm` (LLM вывела `<finishdialog/>`).
2. Оператор нажал "Завершить и оценить" в UI.
3. (НЕ запускается на тех-фейлах и таймерах — там оценщик не нужен,
   причина закрытия и так известна.)

**Парсинг ответа** — теги по аналогии с `<msg>`/`<finishdialog>`:
```
<verdict>success|archive</verdict>
<name>...</name>
<age>...</age>
<city>...</city>
<workplace>...</workplace>
<interests>...</interests>
```

Если `<verdict>` не нашли — один ретрай. Если опять мимо —
`verdict=archive`, отчёт в папку `archive/` (для ручного разбора).

**Таблица `lead_evaluations`** (собственность модуля):
```
lead_evaluations
├── id PK
├── dialog_id        int FK dialogs UNIQUE
├── verdict          text       'success' | 'archive'
├── extracted_name      text NULL
├── extracted_age       smallint NULL
├── extracted_city      text NULL
├── extracted_workplace text NULL
├── extracted_interests text NULL
├── raw_response     text       полный ответ LLM (для аудита)
├── evaluator_model  text
├── parse_succeeded  bool
├── evaluated_at     timestamp
└── created_at, updated_at
```

`UNIQUE(dialog_id)` — при переоценке делаем UPSERT, не плодим истории.

## События на шине

**Новые типы:**

| Тип | Кто публикует | Кто слушает | Полезная нагрузка |
|---|---|---|---|
| `partner_crm.lead_taken` | partner_crm | UI/архив | `{username, gender}` |
| `partner_crm.pool_refilled` | partner_crm | UI | `{count_added}` |
| `partner_crm.status_pushed` | partner_crm | UI/архив | `{username, status, ok}` |
| `partner_crm.status_push_failed` | partner_crm | UI/архив | `{username, status, error}` |
| `lead_evaluator.started` | lead_evaluator | UI | `{dialog_id}` |
| `lead_evaluator.completed` | lead_evaluator | partner_crm | `{dialog_id, verdict, extracted}` |
| `lead_evaluator.failed` | lead_evaluator | UI/архив | `{dialog_id, error}` |

**Используем существующие:**
- `dialog.status_changed` — слушает `partner_crm` для финализации.
- `autochat.finished_by_llm` — слушает `lead_evaluator`.
- `autochat.session_error` (resolve/send_first failed) — слушает `partner_crm`,
  ставит пузырь "Невалид" через `dialog_statuses`.

## HTML-отчёт

Сейчас один общий бакет `MINIO_REPORTS_BUCKET=autochat-reports`. Меняется
не сам бакет, а **префиксы (папки)** внутри:

```
success/{worker_alias}_{username}_{timestamp}.html   ← verdict=success
failed/{worker_alias}_{username}_{timestamp}.html    ← verdict=archive + no_response timer + invalid
archive/{worker_alias}_{username}_{timestamp}.html   ← парсинг ответа LLM сломан
```

В HTML добавляется блок "Оценка лида" (если есть данные из `lead_evaluations`):
```
─── Оценка лида ──────────────────────
Вердикт:        Успешно / Провал
Имя:            ...
Возраст:        ...
Город:          ...
Место работы:  ...
Интересы:       ...
─────────────────────────────────────
```

Триггер генерации сдвигается с `autochat.finished_by_llm` на
`lead_evaluator.completed` (или эквивалент для не-оценочных закрытий).
Для тех-фейлов / таймеров — блок "Оценка лида" не отображается.

## Таймеры тишины

Внутри `lead_evaluator` (потому что это та же тема — реагируем на бездействие)
живёт фоновая задача "watcher silence", раз в `lead_evaluator.silence_check_interval_sec`:

```sql
SELECT d.id, d.status_id, m.last_at
FROM dialogs d
LEFT JOIN LATERAL (SELECT MAX(date) AS last_at FROM messages WHERE dialog_id = d.id) m ON TRUE
WHERE d.status_id находится среди {Первый контакт, Общение, Обрыв}
```

Логика:
- статус "Первый контакт" + last_at > 2 сут назад → ставим "Завершен провал"
  (`partner_crm_terminal_reason='no_response'`).
- статус "Общение" + last incoming > 4 часа назад → ставим "Обрыв".
- статус "Обрыв" + last_at > 2 сут назад → ставим "Завершен провал"
  (`partner_crm_terminal_reason='no_response'`).

Финализирующие изменения публикуют `dialog.status_changed` — `partner_crm`
подхватит и сделает push в CRM.

## Настройки в `settings`

| Ключ | Дефолт | Назначение |
|---|---|---|
| `partner_crm.poll_interval_sec` | `60` | как часто сторож смотрит размер пула |
| `partner_crm.pool_low_threshold` | `10` | ниже какого размера запрашиваем дозалив |
| `partner_crm.refill_batch_size` | `50` | сколько лидов запрашиваем за раз |
| `lead_evaluator.silence_check_interval_sec` | `300` | как часто проверяем таймеры тишины |
| `lead_evaluator.silence_to_obryv_hours` | `4` | от ответа до Обрыва |
| `lead_evaluator.silence_to_close_hours` | `48` | от Обрыва / Первого контакта до Завершен провал |
| `lead_evaluator.parse_retries` | `1` | сколько раз ретраим парсинг |

В `.env`:
```
OPENROUTER_MODEL_EVALUATOR=anthropic/claude-opus-4-7
```

## UI

Куда что втыкается — без новых страниц:

**Страница "Аккаунты"** (внутри `WorkerPromptPage` или в виде расширения карточки):
- Селект `lead_source` (Ручной / CRM пул).
- При `partner_crm` — селект `target_gender` (Любой / Женский / Мужской).
- Бэдж "Лидов в пуле сейчас: N".
- Кнопка "Забрать N лидов из CRM сейчас" (ручной триггер refill).

**Страница "Диалоги"** (`DialogsPage`):
- В списке диалогов — значок если `from_crm=TRUE` (отличие от ручных).
- В фильтрах — переключатель "Все / Только CRM / Только ручные".
- В карточке диалога — блок "Лид из CRM": gender (+ link в CRM если будет).
- В карточке диалога — блок "Оценка лида" (`lead_evaluations`).
- Кнопка "Завершить и оценить" — публикует `lead_evaluator.requested` (ручной триггер оценщика).

**Страница "Настройки"** (`SettingsPage`):
- Раздел "Оценщик лидов":
  - Кнопка "Редактировать промт" → `prompts/lead_evaluator_system.md`
    (тот же `freeform_prompt_editor` что и у autochat).
  - Поля таймеров: silence_to_obryv_hours, silence_to_close_hours, parse_retries.
- Раздел "Партнёрский CRM":
  - Поля `pool_low_threshold`, `refill_batch_size`, `poll_interval_sec`.

## Открытые вопросы (если всплывут — апдейтим этот файл секцией "Уточнения по ходу")

- Поддерживает ли партнёрская CRM переоткрытие лида после терминального статуса —
  пока считаем, что нет (защита от регресса в UI).
- Двусторонняя синхронизация (если партнёр сам поменяет статус на их стороне) —
  отложено. Сейчас работает только в одну сторону: мы → они.
- Управление CRM-preferences (`gender_filter`, `geo_filter`) из нашего UI —
  отложено. Пока считаем, что preferences настраивает админ CRM на их стороне.
