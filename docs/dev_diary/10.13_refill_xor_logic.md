# 10.13 — Рефилл: либо назначенные, либо request-new (не оба)

**Дата:** 2026-05-19
**Этап:** 10.13

## Что изменилось против 10.12

Оператор уточнил: лидов из партнёрского пула надо брать только когда
свой пустой. Если на нашем профиле в CRM уже висят назначенные
свежие лиды — забираем их и **не** дёргаем request-new.

Цель — экономия квоты у партнёра (`max_concurrent_leads=100`): не качать
впрок если у нас уже есть свежий запас.

## Новая логика `refill_pool(count)`

```
1. GET /api/l1/leads?status=new
   ├─ есть свежие → забираем ВСЕ, /status in_progress по каждому
   │                  возвращаем result.phase="assigned"
   │                  (count игнорируется — берём столько сколько есть)
   │
   └─ ничего нет  → POST /request-new {count: N}
                    забираем всё что прилетело, /status in_progress
                    возвращаем result.phase="request_new"
```

`count` в этой схеме контролирует ТОЛЬКО второй случай (request-new).
В первом — берём столько сколько CRM нам реально назначила.

## Файлы

- `modules/partner_crm/service.py:refill_pool` — переписан под XOR

## Чем отличается от 10.12

Было: phase1 + phase2 (обе всегда). Если на профиле 100 свежих
плюс мы хотим 50 новых → результат 150 в пуле, 50 квоты партнёра
истрачены без нужды.

Стало: phase1 OR phase2. Если phase1 что-то дал — phase2 не запускается.
Если phase1 пуст — phase2 берёт `count` новых.

Sequential работа сторожа пула:
- пул < threshold → refill(50)
- если на профиле 100 свежих → берём 100, пул растёт, request-new не зовётся
- следующий тик → пул всё ещё ≥ threshold, не рефиллим
- ... воркер потихоньку выбирает из пула
- пул < threshold → refill(50)
- на профиле 0 свежих (уже все были в работе) → request-new 50

Получается естественный конвейер: новых из request-new берём только
по факту опустошения локального пула И отсутствия "невостребованного"
на нашем профиле.

## Проверка

```bash
# После прошлого теста все 106 лидов на профиле уже in_progress.
# /leads?status=new вернёт 0.

curl -X POST http://localhost:8000/partner-crm/pool/refill \
  -H "Content-Type: application/json" -d '{"count":5}' | jq
# {
#   "requested": 5,
#   "phase": "request_new",      ← phase1 не сработал, перешли в phase2
#   "from_assigned": 0,
#   "from_request_new": 5,
#   "inserted": 5,
#   ...
# }
```

В UI `/settings → Партнёрский CRM` бэйдж "В пуле" должен показать +5.
