# 10.8 — HTML-отчёт: три папки + блок "Оценка лида"

**Дата:** 2026-05-17
**Этап:** 10.8

## Что сделано

Перестроили генерацию HTML-отчёта по диалогу:

- Триггер сдвинут с `<finishdialog/>` (сразу) на `dialog.status_changed`
  с терминальным пузырём (после оценщика). Теперь файл строится когда
  итог уже известен.
- В MinIO бакет `autochat-reports` пишем с префиксом-папкой:
  - `success/` — оценщик: `verdict=success`
  - `archive/` — оценщик: `parse_succeeded=false` (LLM-ответ битый)
  - `failed/` — всё остальное: `verdict=archive`, таймер закрыл, оператор
    вручную поставил Невалид/Завершен провал
- В шапке отчёта добавился блок "Оценка лида" — вердикт + извлечённые
  поля (имя, возраст, город, работа, интересы). Если evaluation для
  диалога нет (таймер / ручной финал) — блок не отображается.
- В badge'е "завершён LLM" теперь название пузыря: "закрыт: Завершен
  успешно" / "Невалид" / "Завершен провал" / "Обрыв".

## Файлы

- `modules/autochat/report.py`:
  - `_load_report_context_by_dialog(dialog_id)` — новая загрузка
    контекста по dialog_id (вместо session_id), JOIN'ит
    `lead_evaluations`, `dialog_statuses`, autochat-сессию (если есть)
  - `_determine_folder(ctx)` — мапит вердикт → имя папки
  - `_build_storage_key` — теперь префикс с папкой
  - `_eval_block_html` — генератор HTML-блока оценки
  - `build_html` — встраивает блок + меняет надпись на бэйдже
  - `save_report_for_dialog(dialog_id)` — новая точка входа
  - `save_report_for_session` оставлен как тонкая обёртка (backward compat)
  - CSS: `.eval-block`, `.eval-row`, `.verdict-success/.verdict-archive`
- `modules/autochat/report_consumer.py` — новый bus-consumer
  на `dialog.status_changed`, при терминальном пузыре зовёт
  `save_report_for_dialog`
- `modules/autochat/service.py`: убрал прямой вызов
  `save_report_for_session` из `_on_session_finished_by_llm` — теперь
  он делает только `stop_session`, отчёт строится отдельно по факту
  terminal-status
- `api/main.py`: регистрация `ReportConsumer` в lifespan

## Поток рисования отчёта

```
[Любой путь закрытия диалога:]
  оценщик    → set_dialog_status("Завершен успешно" / "Завершен провал")
  silence_watcher → set_dialog_status("Завершен провал")
  оператор   → set_dialog_status(терминальный)
  autochat resolve/send упал → set_dialog_status("Невалид")  (10.4)
        │
        ▼ event dialog.status_changed
ReportConsumer
        │ status_id terminal? (partner_terminal_status IS NOT NULL)
        ▼ да
save_report_for_dialog(dialog_id)
        │ _determine_folder по eval_verdict/parse_succeeded
        │ build_html с _eval_block_html(ctx)
        ▼
MinIO: {folder}/{worker}_@{username}_dd-mm-yy_hh-mm.html
publish autochat.report_saved {dialog_id, minio_key, folder}
```

## Почему так, а не иначе

**Триггер по `dialog.status_changed`, а не по `lead_evaluator.completed`.**
Хочется одного механизма для всех путей закрытия — оценщика, таймера,
ручного оператора. Все три проставляют пузырь через
`dialog_statuses.set_dialog_status` → событие `dialog.status_changed`.
Подписываемся на него.

**Backward-compat: `save_report_for_session` оставлен.** Сохранили
эндпоинт `POST /autochat/sessions/{id}/build-report` — оператор
из UI может перестроить отчёт по конкретной сессии. Внутри он
резолвит `session_id → dialog_id` и зовёт новую функцию.

**Папка `archive/` — только для случая когда LLM нам ответил
непарсящимся ответом и после ретрая.** Не "evaluator сказал archive",
а конкретно "не смогли понять что сказал LLM". Эти отчёты — для
ручного разбора оператором (увидеть в `raw_response` что он там
сгенерил). Все остальные "archive verdict" нормально валятся в
`failed/`.

**Тут же убрана генерация отчёта из `_on_session_finished_by_llm`.**
Раньше она была "сразу после finish-by-LLM" — на тот момент оценка
ещё не сделана, eval_* поля пустые. Теперь отчёт ждёт terminal
status и видит уже заполненный `lead_evaluations`. Если оценщик
упадёт по сети — silence_watcher через 48ч закроет диалог в "Завершен
провал" (без eval-блока) → отчёт всё равно появится, просто в
`failed/` без полей.

## Проверка

Контейнер `app` поднялся. `ReportConsumer` зарегистрирован в
lifespan. Файлы будут появляться когда первый CRM-диалог дойдёт
до терминального пузыря.

Можно проверить вручную: `POST /lead-evaluator/dialogs/{id}/evaluate`
на готовом диалоге → оценщик поставит пузырь → consumer построит отчёт.

## Открытые вопросы

- В `events_archive` теперь у `autochat.report_saved` появилось поле
  `folder` — UI может это использовать для иконки в ленте.
- Старые отчёты (созданные до 10.8) лежат в корне бакета, новые —
  в папках. Историческая миграция (перемещение) не нужна — старые
  открываются без проблем по своим ключам.
