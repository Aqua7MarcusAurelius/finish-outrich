## Что сделано

В правую колонку страницы "Диалоги" добавили панель "Лид" — над
существующим виджетом событий. Внутри:

- Бэйдж "Из CRM / Ручной"

для лидов из партнёрского CRM (быстрая визуальная фильтрация).

## Поведение

**Если оценщика не было** (autochat ещё не дошёл до finishdialog,
оператор не нажимал кнопку) — в блоке надпись "Оценщик ещё не
отработал" + кнопка "Завершить и оценить" доступна.

**Если оценщик отработал** — блок показывает иконку успех/провал,
название модели и таблицу `Имя/Возраст/Город/Место работы/Интересы`
(только те поля что не NULL). Кнопка превращается в "Переоценить" —
UPSERT в `lead_evaluations` по уникальности `dialog_id`.

**Если парсинг сломан** (`parse_succeeded=false`) — заголовок
"Парсинг сломан — разобрать вручную", модель указана. Поля
могут быть пустыми. HTML-отчёт по такому диалогу попадёт в
папку `archive/` (10.8).

**Polling.** `useQuery` на `/lead-evaluator/dialogs/{id}/evaluation`
с `refetchInterval=10s` — после `<finishdialog/>` оценщик отработает
асинхронно, UI подхватит обновление без явного refresh'а от
пользователя.

## Почему так, а не иначе

**Кнопка "Переоценить" доступна всегда** — оператор может править
промт в настройках и хотеть переоценить уже закрытый диалог.
`evaluate` идемпотентен (UNIQUE на `dialog_id` + UPSERT).

**Кнопка ставит терминальный пузырь как побочный эффект.** Оценщик
внутри (`service.py:_evaluate_inner`) после получения вердикта
зовёт `dialog_statuses.set_dialog_status`. Это значит:
если оператор переоценит и LLM сменит вердикт — пузырь тоже
поменяется. Для оператора это ожидаемо: "переоценить" = "пересмотреть
итог", не "просто посмотреть результат".

**Бэйдж "→ CRM: ..." виден, только если статус ещё ждёт push'а.**
После того как `partner_crm.finalizer` (10.7) отправит финал и
очистит `partner_crm_terminal_reason` в NULL — бэйдж пропадает.
Это естественный индикатор "пушнули / ещё не пушнули".

**Маленький "CRM" бэйдж в списке слева.** Видно у каждой строки
без открытия диалога — оператор может бегло отфильтровать
свои дела от CRM-конвейера.

## Проверка

```bash
curl http://localhost:8000/dialogs/617 | jq '{gender, from_crm, partner_crm_terminal_reason}'
# { "gender": null, "from_crm": false, "partner_crm_terminal_reason": null }
```

В UI — открыть любой диалог → справа над виджетом событий появилась
панель "Лид". Для CRM-лида (из пула) бэйдж "Из CRM" будет синим.

Кнопка "Завершить и оценить" дёргает оценщика синхронно — на
не-CRM диалогах тоже работает (вердикт всё равно положится в
`lead_evaluations`, но в CRM ничего не пойдёт потому что
`from_crm=false`).

## Открытые вопросы

- Если LLM-оценщик упадёт по сети (OpenRouterError) — UI получит
  502, в toast вылетит ошибка. Защитного фолбэка пока нет —
  оператор увидит и нажмёт ещё раз.
- Длительность оценки может быть 5-15 секунд. Спиннер в кнопке
  есть; в UI остального пути блокировки нет — оператор может
  параллельно делать другое. Это норм.
